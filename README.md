# בוט תקנון בית הספר (RAG)

מערכת שמאפשרת לתלמידות לשאול שאלות על תקנון בית הספר ולקבל תשובות **רק מתוך מסמכי התקנון**.
המערכת בנויה בשיטת RAG (Retrieval-Augmented Generation): לפני שהמודל עונה, היא שולפת מהתקנון את הקטעים הרלוונטיים לשאלה, והמודל עונה רק לפיהם.

**טכנולוגיות:** Python · LlamaIndex · ChromaDB · Google Gemini (API חינמי) · Streamlit

---

## איך המערכת עובדת

**שלב א – קליטה (`ingest.py`, פעם אחת):**

```
קבצי WORD ─► ניקוי טקסט ─► חלוקה ל-chunks ─► יצירת וקטורים (Gemini) ─► שמירה ב-ChromaDB
```

**שלב ב – שאלה ותשובה (`app.py` / `rag.py`, בכל שאלה):**

```
שאלת התלמידה ─► (הרחבת שאלה) ─► וקטור לשאלה ─► חיפוש TOP K קטעים ב-ChromaDB
              ─► הקטעים + השאלה נשלחים ל-Gemini ─► תשובה + מקורות
```

---

## מבנה הפרויקט

| קובץ / תיקייה | תפקיד |
|---|---|
| `config.py` | **כל ההגדרות וההחלטות של המערכת** במקום אחד, כולל ה-PROMPT |
| `ingest.py` | קריאת קבצי ה-WORD, חלוקה ל-chunks ושמירה ב-ChromaDB |
| `rag.py` | מנוע השאלות: הרחבת שאלה, חיפוש ויצירת תשובה |
| `app.py` | ממשק הצ'אט לתלמידות (Streamlit) |
| `models.py` | יצירת מודלי Gemini (וקטורים ותשובות) |
| `data/` | קבצי התקנון (`.docx`) |
| `chroma_db/` | מסד הנתונים הווקטורי (נוצר אוטומטית) |
| `.env` | מפתח ה-API (לא משותף ולא עולה ל-git) |

## התקנה

1. **Python 3.13** מותקן במחשב.
2. יצירת סביבה וירטואלית והתקנת הספריות (בטרמינל, מתוך תיקיית הפרויקט):
   ```
   py -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   ```
3. **מפתח API:** יוצרים מפתח חינמי ב-[Google AI Studio](https://aistudio.google.com/apikey).
   יוצרים בתיקיית הפרויקט קובץ בשם `.env` (אפשר להעתיק מ-`.env.example`) עם השורה:
   ```
   GOOGLE_API_KEY=המפתח-שלך
   ```
4. מעתיקים את קבצי התקנון (`.docx`) לתיקייה `data/`.

---

## הרצה

**1. קליטת התקנון ל-ChromaDB:**
```
.venv\Scripts\python.exe ingest.py
```
הסקריפט מדפיס את כל ה-chunks שנוצרו, וכך אפשר לראות את השפעת הגדרות החלוקה.

**2. הפעלת הצ'אט:**
```
.venv\Scripts\streamlit.exe run app.py
```
הצ'אט נפתח בדפדפן בכתובת **http://localhost:8501**.

**בדיקה מהירה בלי ממשק** (מדפיס תשובה, קטעים שנשלפו וציוני התאמה):
```
.venv\Scripts\python.exe rag.py "מה מותר ללבוש בחורף?"
```

### מתי צריך להריץ שוב את `ingest.py`?

| שינוי | `ingest.py` מחדש? |
|---|---|
| הוספה או עדכון של קובץ תקנון | ✅ כן |
| שיטת חלוקה / גודל chunk / חפיפה | ✅ כן |
| מודל הוקטורים (`EMBEDDING_MODEL`) | ✅ כן |
| מודל התשובות, Top K, צורת חיפוש, הרחבת שאלה, PROMPT | ❌ לא, מספיק להפעיל מחדש את הצ'אט |

## נקודות ההחלטה

כל ההחלטות מוגדרות ב-`config.py` וניתנות לשינוי בלי לגעת בשאר הקוד.

| # | החלטה | הבחירה | משתנה ב-`config.py` |
|---|---|---|---|
| 1 | Vector DB | **ChromaDB**, נשמר מקומית על הדיסק, עם מרחק קוסינוס | `CHROMA_DIR` |
| 2 | ספרייה | **LlamaIndex** | – |
| 3 | שיטת חלוקה | **לפי טוקנים**, ‏512 טוקנים ל-chunk (אפשרויות: `tokens` / `words` / `semantic`) | `CHUNKING_METHOD`, `CHUNK_SIZE` |
| 4 | חפיפה בין chunks | **כן**, ‏50 טוקנים | `USE_CHUNK_OVERLAP`, `CHUNK_OVERLAP` |
| 5 | API KEY | **Google Gemini**, מכסה חינמית | `.env` |
| 6 | Top K | **5** קטעים בכל חיפוש | `TOP_K` |
| 7 | מודלים | וקטורים: **gemini-embedding-001** · תשובות: **gemini-3.5-flash-lite**, עם גיבוי אוטומטי ל-gemini-3.5-flash ול-gemini-3.1-flash-lite | `EMBEDDING_MODEL`, `LLM_MODEL`, `LLM_FALLBACK_MODELS` |
| 8 | הרחבת שאלה | **לא** (אפשר להפעיל) | `USE_QUERY_EXPANSION` |
| 9 | צורת חיפוש | **similarity**, דמיון קוסינוס (אפשרות נוספת: `mmr`) | `SEARCH_MODE` |

### הסבר על ההחלטות

**3 – חלוקה לפי טוקנים.** השיטה הזו לא עולה קריאות API בזמן החלוקה, בניגוד לחלוקה לפי משמעות שמחשבת וקטור לכל משפט. בנוסף, `SentenceSplitter` לא חותך משפט באמצע.
*תצפית:* התקנון קצר מאוד (כ-500 מילים ב-6 קבצים). עם 512 טוקנים נוצרים 7 chunks, כמעט chunk אחד לכל קובץ.

**4 – חפיפה.** כשכלל נחתך בין שני chunks, החפיפה שומרת על ההקשר שלו. ההוספה לאחסון ולעלות זניחה.

**5 – Gemini.** יש לו מכסה חינמית שמספיקה לפרויקט, והוא תומך היטב בעברית.

**6 – Top K = 5.** הקטע הנכון דורג ראשון בכל הבדיקות.
*תצפית:* מכיוון שיש רק 7 chunks, ‏5 קטעים הם כמעט כל התקנון. ערך של 2–3 יחזיר פחות קטעים לא רלוונטיים.

**7 – מודלים.**
- `gemini-embedding-001` הוא מודל וקטורים רב-לשוני. המערכת יוצרת וקטורים נפרדים למסמכים (`RETRIEVAL_DOCUMENT`) ולשאלות (`RETRIEVAL_QUERY`), מה שמשפר את החיפוש.
- המודלים נבחרו אחרי בדיקה של מה שזמין במפתח החינמי: `gemini-2.5-flash` כבר לא זמין למשתמשים חדשים, ו-`gemini-3.8-flash` היה עמוס בזמן הבדיקה.
- `gemini-3.5-flash-lite` הוא המודל הראשי. הוא מהיר: ענה במדידה תוך 0.6 שניות, לעומת 2.9 של `gemini-3.5-flash`, שמבצע שלב "חשיבה" לפני התשובה. בנוסף, ל-`gemini-3.5-flash` יש במפתח החינמי מכסה של 20 בקשות ביום בלבד.
- **גיבוי אוטומטי:** כשלמודל נגמרת המכסה (429) או שהשרת עמוס (503), המערכת עוברת למודל הבא ברשימה `LLM_FALLBACK_MODELS`. לכל מודל יש מכסה חינמית נפרדת. מודל שנגמרה לו המכסה מדולג גם בשאלות הבאות, כדי לא לבזבז זמן.
- `LLM_TEMPERATURE = 0.8`. ערך נמוך יותר (0–0.3) נותן תשובות עקביות ונאמנות יותר למקור.

**8 – הרחבת שאלה כבויה.** ההרחבה מוסיפה קריאת API בכל שאלה, ובבדיקות החיפוש מצא את הקטע הנכון גם בלעדיה. היא שימושית לשאלות קצרות מאוד, למשל "סוודר?".

**9 – similarity.** בתקנון קטן ולא חוזר על עצמו אין כמעט קטעים כפולים, ולכן MMR (שנועד לגוון את התוצאות) לא נחוץ.

## התאמת כללי התשובה (PROMPT)

בסוף `config.py`, בחלק **"הנחיות למודל (PROMPT)"**:

| משתנה | מה הוא קובע |
|---|---|
| `ASSISTANT_ROLE` | תפקיד הבוט |
| `ANSWER_RULES` | רשימת כללי התשובה, שורה לכל כלל |
| `NOT_FOUND_ANSWER` | התשובה כשהמידע לא נמצא בתקנון |
| `EXPANSION_INSTRUCTIONS` | ההנחיה להרחבת השאלה |

**הכללים הנוכחיים:** לענות רק מהקטעים שנשלפו, בלי ידע כללי · אם אין תשובה, להחזיר את `NOT_FOUND_ANSWER` · לענות בעברית ובקצרה · לציין מקור.

**זהירות:** אין לכתוב סוגריים מסולסלים `{ }` בתוך הכללים.

## פתרון בעיות

| שגיאה | סיבה ופתרון |
|---|---|
| `CERTIFICATE_VERIFY_FAILED` | רשת מסוננת (למשל נטפרי) עם תעודת אבטחה משלה. המערכת משתמשת ב-`truststore` כדי לאמת מול מאגר התעודות של Windows (מוגדר ב-`models.py`). |
| `404 NOT_FOUND` – model is no longer available | המודל הוצא משימוש. יש להחליף את `LLM_MODEL` ב-`config.py` למודל זמין. |
| `503 UNAVAILABLE` | שרתי Gemini עמוסים. המערכת מנסה שוב אוטומטית; אם זה ממשיך, לנסות מאוחר יותר או להחליף מודל. |
| `429` | הגעה למגבלת המכסה החינמית. המערכת עוברת אוטומטית למודל גיבוי. אם המכסה של כל המודלים נגמרה: מגבלה לדקה מתחדשת תוך דקה, ומגבלה יומית מתחדשת למחרת. הניצול מוצג ב-[ai.dev/rate-limit](https://ai.dev/rate-limit). |
| "ה-DB ריק" | לא הורץ `ingest.py`. |
| "ה-DB נבנה עם מודל אחר" | `EMBEDDING_MODEL` שונה אחרי הקליטה. יש להריץ שוב את `ingest.py`. |
